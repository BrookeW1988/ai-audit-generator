# Intake form: setup audit

**What it's for:** the client fills it in before the paid session, alongside the take-stock prompt. The form tells you what they want and what hurts. The snapshot tells you what's actually there. Every question maps to a fact in `references/what-a-good-audit-needs.md` (the IDs are in the table at the bottom, which never goes to the client).

**How to use it:** paste the questions into Google Forms, Tally or Typeform, or send it as a doc. Put the link in your brand sheet as [INTAKE FORM LINK], or keep a separate link for setup audits.

Copy from the line below to the end of the questions.

---

## Before our session: [CLIENT BUSINESS]

This takes about 15 minutes. Short answers are fine. Rough numbers are fine. "Not sure" is a useful answer too.

Please don't paste any passwords or API keys into this form. Where a question asks about them, just say where they live.

**What you've built**

1. List what you've built, one line each: what it does and how it starts (you type something, it runs on a schedule, or something else sets it off).
2. Which tools is it built in? *(e.g. Claude Code, Claude Cowork, ChatGPT, Zapier, n8n)* Which Claude plan are you on, if you know?
3. Does your computer need to be on for it to run?

**The one that's giving you trouble**

4. Which one do you most want fixed?
5. What should it give you when it works? If you have a good example, keep it handy for our session.
6. What happens instead? *(e.g. it stalls, needs restarting, gets details wrong, misses some, does some twice)*
7. When did it last run all the way through on its own? Did anything change around then, like more work, a new tool or an update?
8. What do you do when it goes wrong? Roughly how long does that take each time, and how often does it happen?
9. How much does it handle in one go? *(e.g. "8 to 10 call recordings, about an hour each")*

**Keeping it safe**

10. Does it touch client information, or send anything on its own (emails, messages, posts)?
11. Where do the API keys or passwords it uses live? Just say where, never the key itself. *(e.g. "in a .env file", "in my instructions", "not sure")*
12. Is your setup backed up anywhere, like GitHub or a copy on another drive?
13. Does anyone else rely on what it produces? Could anyone else run it if you were away?

**Looking ahead**

14. Do you want it fixed for you, or fixed and explained so you can keep building yourself?
15. What would you like to build next?
16. Is there anything you'd rather I didn't touch?
17. Roughly what's an hour of your time worth? Skip it if you'd rather not say.

Thanks! I'll also send you a short prompt that takes a snapshot of your setup. It only reads, and it hides your keys.
[YOUR FIRST NAME]
